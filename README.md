# Arbor QSF Streamlit Explorer

This repository is generated from an Arbor TLS/MLS interactive report.

The app displays:

- stand-level QSM statistics
- clickable tree map
- individual QSM + point-cloud overlay
- DBH / height / volume relationships
- woody architecture and branch-order summaries
- QSF semantic reclassification summaries
- structural tree rankings
- complete searchable inventory

## 1. Build this repository from your Arbor results

Keep these template files together:

```text
app.py
build_streamlit_repo.py
requirements.txt
.streamlit/config.toml
README.md
```

Run:

```bash
python build_streamlit_repo.py "C:\path\to\plot_arbor_results" "C:\path\to\arbor_streamlit_repo"
```

The builder reads `Arbor_interactive_explorer.html` for report metadata and copies
the data/viewer files required by the Streamlit application.

## 2. Test locally

```bash
cd C:\path\to\arbor_streamlit_repo
pip install -r requirements.txt
streamlit run app.py
```

## 3. Upload to GitHub

Create a GitHub repository and upload the complete generated folder, including:

```text
app.py
requirements.txt
.streamlit/
data/
```

Do not omit `data/QSM_viewers/`, because those files contain the individual-tree
3D QSM + point-cloud viewers.

## 4. Deploy with Streamlit Community Cloud

Open:

https://share.streamlit.io/

Create an app and select:

- your GitHub repository
- your branch
- `app.py` as the entrypoint

Streamlit Community Cloud executes from the repository root, so keep the file
structure generated by the builder.

## Repository size

The individual QSM viewer pages may make the repository large. GitHub rejects
individual files larger than 100 MB. The builder prints the largest files and
warns if any file approaches that limit.

If the repository becomes too large, reduce `pointcloud_points_per_tree` in the
R report-generation workflow and regenerate the QSM viewers before rebuilding
this Streamlit repository.
